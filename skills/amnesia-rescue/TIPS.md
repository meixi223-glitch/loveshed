# 人读版 · 失忆抢救 / Amnesia Rescue — the human version

> 这是给人看的版本：不写代码、不敲命令。TA 好像把最近几天整块忘了——你能自己做的，是**证明缺口、量出缺口、找到线索**；真正修记忆系统，交给施工队。给施工 agent 装的机读版在 [SKILL.md](SKILL.md)。
>
> This is the version for people: no code, no command line. Your companion seems to have lost a whole stretch of days. What you can do yourself is **prove the gap, measure it, and find the clue**; actually repairing the memory system is a job for a crew. The agent-facing version is [SKILL.md](SKILL.md).

**类型 / Type：一半自己做 · Half by hand**
找证据和拍板你来；修复和补数据需要施工队。
You gather evidence and make the calls; the repair and the backfill need a crew.

## 中文

### 先分清：是"零星忘"还是"整块丢"

偶尔忘一两件事，先走 [降智自检](../degradation-checkup/TIPS.md)。
如果是**某几天的事几乎全不记得**，而那几天你们明明聊了很多——那多半是记忆系统漏收了，往下看。

### 你自己能做的部分

**1. 拿数字说话，画一张缺口表**

挑最近 7–10 天，每天问 TA 一个具体问题（"3 号晚上我们聊了什么？"），再去记忆页 / 日记 / 每日总结里找那天的记录。填这张表：

| 日期 | 那天聊得多吗 | TA 记得吗 | 记忆里有没有 |
|---|---|---|---|
| 某月 1 日 | 多 | 记得 | 有 |
| 某月 2 日 | 多 | 不记得 | 没有 |
| … | | | |

**2. 找规律**
- 缺口从**哪一天开始**？到哪一天结束？
- 那几天你有没有**换了聊天的入口**？比如开始用一个新 App、新页面、新的发消息方式？
- 是**你的话**丢了，还是**TA 的话**也丢了？

真实案例里，缺口恰好从用户开始用一个新聊天页的那天开始：新页面发的消息被系统误当成了"系统通知"，整类过滤掉了。**"那天开始换了什么"是最值钱的线索。**

**3. 别被第一个答案打发**

施工队查完说"××没问题"，不代表没故障。拿你的缺口表追问："那为什么这几天的记录对不上？"

**4. 这些由你拍板**
- **要不要重新生成那几天的日记 / 总结？** 那是你们共同的回忆，你可能想保留原样。要换的话，让施工队**先把旧版存档**。
- **情绪、心情这类"状态"不要补。** 补算几天前的情绪，会把过时的起伏叠加到现在。只补"发生过的事"。

**5. 以后每周自查一次**

随便挑最近三天，各问 TA 一个具体问题。答不上来，趁早查。

### 需要施工队的部分

定位是哪段程序过滤错了、修好、把漏掉的几天补回去——这些得交给施工 agent。把缺口表一起发给它（它读不到网页的话，就把 SKILL.md 全文粘贴给它）：

> 请先读这份施工工艺：https://github.com/meixi223-glitch/loveshed/blob/main/skills/amnesia-rescue/SKILL.md
> 按它在我的环境里施工，规矩如下：
> 1. 先只做调查：把现场情况和你的施工计划发给我，我说可以再动手；
> 2. 动手前先备份，并告诉我改坏了怎么退回去；
> 3. 测试一律用测试账号或假入口，绝不往我和 TA 的真实对话里发消息；
> 4. 做完按这个格式汇报：结论 / 做了什么 / 证据 / 没做的或需要我决定的 / 怎么退回去 / 备份在哪。
>
> 附：这是我自己整理的缺口表（粘贴表格）。缺口从这一天开始，那天我开始用了：（新入口）。

**收活时你可以问的：**
- "所有会漏掉这类消息的地方都改了吗？还有哪些没改？"
- "漏掉的那几天补回来了吗？补了多少条，有没有重复？"
- "旧的日记 / 总结存档在哪？"

如果你用的是现成平台、没有施工队，可以手动"补课"：见 [回填人读版](../backfill-rate-limit/TIPS.md)。

## English

### First: scattered forgetting, or a missing block?

Forgetting one or two things now and then? Start with the [degradation checkup](../degradation-checkup/TIPS.md).
If **almost nothing from certain days** is remembered, even though you talked a lot on those days, the memory system probably missed them. Read on.

### What you can do yourself

**1. Use numbers: make a gap table**

Take the last 7–10 days. For each day, ask your companion one concrete question ("What did we talk about on the evening of the 3rd?"), then look for that day on the memory page, diary, or daily summary. Fill in:

| Date | Talked a lot? | Do they remember? | In memory? |
|---|---|---|---|
| Day 1 | yes | yes | yes |
| Day 2 | yes | no | no |
| … | | | |

**2. Look for the pattern**
- On **which day** does the gap start? When does it end?
- Did you **change how you chat** around then? A new app, a new page, a new way of sending messages?
- Is it **your words** that are missing, or **theirs** too?

In the real case, the gap started on exactly the day the user began chatting through a new chat page: messages from that page were mistaken for "system notifications" and filtered out as a whole class. **"What changed on the day it started" is the most valuable clue.**

**3. Don't accept the first answer**

If the crew checks something and says "X is fine", that doesn't mean nothing's broken. Use your gap table: "Then why don't these days line up?"

**4. These calls are yours**
- **Regenerate the diary / summaries for those days?** They're shared memories; you might want to keep them as they are. If you do replace them, have the crew **archive the old version first**.
- **Don't backfill "states" like mood.** Recomputing how they felt days ago layers stale ups and downs onto today. Backfill what happened, not how things were.

**5. A weekly self-check from now on**

Pick any of the last three days and ask one concrete question about each. If they can't answer, look into it early.

### The part that needs a crew

Finding which part of the program filtered wrongly, fixing it, and bringing the missing days back is a job for a builder agent. Send this along with your gap table (if it can't open web pages, paste the full SKILL.md instead):

> Please read this playbook first: https://github.com/meixi223-glitch/loveshed/blob/main/skills/amnesia-rescue/SKILL.md
> Build it in my setup, under these rules:
> 1. Investigate first: send me what you find and your plan, and wait for my OK before changing anything;
> 2. Back up before you touch anything, and tell me how to go back if it breaks;
> 3. Test only with a test account or a fake entry point. Never send messages into the real conversation between me and my companion;
> 4. When done, report as: Conclusion / What you did / Evidence / Not done or needs my decision / How to go back / Where the backup is.
>
> Attached: my own gap table (paste it). The gap starts on this day, which is when I started using: (the new entry point).

**Questions to ask when the work comes back:**
- "Did you fix every place that drops this kind of message? Which ones are left?"
- "Are the missing days back? How many items, any duplicates?"
- "Where are the old diary entries / summaries archived?"

If you're on a ready-made platform with no crew, you can catch them up by hand: see the [backfill human version](../backfill-rate-limit/TIPS.md).
